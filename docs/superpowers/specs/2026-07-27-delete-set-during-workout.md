# Удаление подхода во время тренировки

**Дата:** 2026-07-27
**Статус:** approved (ревизия после ревью — 2026-07-27)

## Контекст

На вкладке «Зал» во время тренировки пользователь может добавлять подходы кнопкой «Добавить подход», но не может удалить лишний/ошибочный подход.

Бэкенд-логика (`removeSet` в `useWorkoutSetActions`, `useWorkoutSession.ts:170`) уже реализована:
- удаляет подход по индексу
- не даёт удалить последний оставшийся (`sets.length <= 1`)
- сохраняет черновик через `persistWorkoutDraft`
- показывает toast-уведомление «Подход удалён» — **но гард стоит внутри `setLogs`, а `notify` снаружи, поэтому тост врёт при заблокированном удалении**

`GymPage` уже принимает `onRemoveSet` проп (строка 61) и получает его из `App.tsx:533`, но не пробрасывает в `GymScreen`.

## Какой подход удаляется

`activeSetIndex = activeLog.sets.findIndex((set) => !set.completed)` (`useActiveWorkoutContext.ts:109`) — это **первый невыполненный** подход, а не последний добавленный.

Кнопка удаляет именно его. Удалять последний (честный undo для «Добавить подход») нельзя: после `editCompletedSet` последний подход может оказаться выполненным, и удаление снесёт записанные данные. Текущий подход всегда невыполненный.

Отсюда подпись с номером — **«Удалить подход N»**, а не «Удалить подход». Без номера кнопка, стоящая под «Добавить подход», читается как отмена добавления и молча удалит подход с уже введённым весом.

### Детали

#### `CurrentStepCard.tsx`
- Новый проп: `removeSet: (setIndex: number) => void`
- Кнопка: после «Добавить подход», внутри `current-step--logger` карточки
- Текст: «Удалить подход {setNumber}» — совпадает с eyebrow карточки «Подход N из M»
- Иконка: `Trash2` из `lucide-react` (нужен импорт в CurrentStepCard)
- Без `aria-label`: он дублировал бы видимый текст. Доступное имя берётся из текста — как у соседней `.gym-remove-exercise-btn` (`GymScreen.tsx:238`), тест которой (`GymScreen.test.tsx:224`) ищет её по имени

#### Стиль кнопки

Нового CSS-блока нет. `.gym-remove-exercise-btn` (`warm-editorial-theme.css:1555`) — ровно нужный стиль, поэтому к нему добавляется второй селектор. `flex`/`gap` не требуются: соседняя кнопка рендерит `<Trash2/> текст` без них.

```css
.gym-remove-exercise-btn,
.gym-remove-set-btn { /* ...тело без изменений... */ }
.gym-remove-exercise-btn:hover,
```

### Состояния и edge-кейсы

| Случай | Поведение |
|---|---|
| Подходов > 1 | Кнопка показывается, удаляет текущий (первый невыполненный) подход |
| Подходов = 1 | Кнопка **не показывается**; плюс гард в хуке возвращает управление до `notify` |
| Все подходы выполнены (`allSetsCompleted`) | Карточка не рендерится (`CurrentStepCard.tsx:77`) → кнопка не видна (ОК) |
| Режим отдыха (`resting`) | Ранний return на таймер (`CurrentStepCard.tsx:94`) → кнопка не видна (ОК) |

### Тестирование

- `CurrentStepCard` — кнопка вызывает `removeSet(activeSetIndex)`; кнопки нет, когда подход один
- `GymScreen` — отдельного теста проброса нет: это ловит `tsc`, а 50 строк пропсов ради проверки типа не окупаются
- Гард в хуке — без отдельного теста: харнесса для `useWorkoutSession` нет, поднимать `renderHook` ради двух строк дороже фикса
- Существующим тестам `GymScreen.test.tsx` понадобится `removeSet={vi.fn()}` в трёх местах (`renderGym` + два полных списка пропсов)

### Не затрагивается

- API/сервер (подходы — часть черновика, сохраняются целиком)
- Чипсы подходов в `GymScreen` — остаются без изменений
- Подтверждение удаления — не нужно: удаляется невыполненный подход, терять нечего
