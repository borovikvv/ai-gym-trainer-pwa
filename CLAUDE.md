## Конвейер задач (2026-08-05)

**Разделение труда.** План и ревью — Claude. Код, тесты, починка CI, правки по замечаниям — исполнитель (ZCode/opencode). Claude код не пишет; исполнитель проектных решений не принимает: если план не сходится с кодом — останавливается и пишет в issue.

**Состояние задачи — метки:** `needs-plan` → `ready-for-code` → PR → `ci-failed` / `changes-requested` → `ready-to-merge`. Мержит только владелец.

**План** (комментарий в issue): файлы, которые можно трогать • шаги • чем проверяется — сценарий и файл теста • потолок диффа. Чего в плане нет — исполнитель не делает, а пишет в issue.

**Исполнитель:** ветка `<тип>/issue-N`, один issue — один PR, дифф маленький. PR открывается только с зелёным локальным CI:

```bash
npm run lint && npx tsc -b && npm test && npm run build
```

Тесты пишет исполнитель в том же PR: изменение поведения без теста — повод вернуть на доработку. Для багов порядок обратный — сначала падающий тест, потом фикс. Рефакторинг без изменения поведения новых тестов не требует.

**Ревью:** `@claude review` в PR. Помимо кода проверяется осмысленность теста: упал бы он, если откатить фикс? Не упал бы — тест подогнан под текущее поведение, `changes-requested`.

**Правило трёх кругов:** третий `changes-requested` по одной задаче → `needs-replan`, задача возвращается на планирование. Не дошлифовываем бесконечно.

**Агенты не правят `.github/workflows/`** — изменения в воркфлоу делает владелец.
